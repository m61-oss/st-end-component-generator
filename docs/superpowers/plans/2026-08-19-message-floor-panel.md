# 楼层面板实现计划

## 目标

在最新 assistant 楼层正文下挂载一个可选的楼层面板。它复用现有生成、解析、锚点编辑、注入与撤回流程，不持久化运行中的预览状态；面板始终只跟随当前聊天的最新 assistant 楼层。

## 实现拆分

1. 新增 `ui/message-floor-panel.js`，提供不依赖 DOM 的状态模型、四种可见状态、动作模型、目标快照校验和生成世代校验。
2. 新增对应测试，覆盖折叠/展开状态、状态标签、目标楼层校验、操作权限和迟到响应失效。
3. 在 `index.js` 中增加运行时楼层面板状态：根据消息事件重新定位楼层，生成开始/流式更新/完成/失败/注入/撤回时同步状态；所有生成请求带目标世代，旧请求不得覆盖新楼层。
4. 楼层面板以消息 DOM 的附属 UI 挂载，不写入 `message.mes`；折叠时只更新状态，展开后才创建/更新思考与结果内容，避免隐藏预览持续重绘。
5. 标准结果使用可编辑文本框，锚点结果复用现有锚点计划数据与编辑逻辑；编辑结果同步到主面板和真实注入源。流式期间只读，注入成功后锁定，撤回后恢复可编辑。
6. 在“界面与快捷入口”加入默认关闭的“最新楼层面板”开关；不新增独立入口、不改变悬浮球设置。
7. 在 `style.css` 增加折叠条、展开面板、状态、思考区、标准/锚点结果和移动端布局样式，使用现有主题变量。

## 验证

- 新增单元测试与现有全量测试。
- `node --check index.js`。
- `git diff --check`。
- 检查面板不修改聊天正文，且目标楼层改变时注入被拒绝。
