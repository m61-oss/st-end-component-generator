# 停止流式生成后的注入与多锚点预览设计

## 目标

生成进行中只提供停止操作。生成请求结束后，只要已收到的内容能够形成至少一个可注入结果，楼层面板就进入待注入状态并显示“重新生成”和“注入回复”。注入操作本身不得负责停止生成。

锚点模式的流式预览必须同时保留已经完成的项目和当前正在生成的项目，避免第二项及后续项目必须等到闭合后才整块出现。

## 状态规则

- 请求仍在生成：仅显示停止生成。
- 请求已经结束且存在可用结果：显示重新生成与注入回复。
- 请求已经结束且没有可用结果：不显示注入。
- 手动停止、网络异常结束和正常结束遵循同一条“请求已结束 + 结果可用”判定。
- 对锚点结果，“可用”表示至少存在一个满足当前位置要求且 `content` 非空的项目。

## 增量解析

宽松锚点解析器应返回所有已经完成的项目，并额外尝试恢复数组末尾当前未完成的项目。恢复过程必须识别 JSON 字符串转义和对象边界，不能把前面项目的字段误当作当前项目。

实时预览继续按项目顺序拼接 `content`。最终生成结束后仍由现有完整结果解析与注入逻辑接管。

## 验证

- 第二个、第三个锚点的未闭合 `content` 会立即出现在预览中。
- 已结束且有部分有效锚点时，楼层面板进入待注入状态。
- 生成中仍只有停止按钮。
- 已结束但没有有效内容时不出现注入按钮。
