# 提示词来源缓存设计

## 目标

缩短点击“生成”到外置 API 请求发出之间的等待时间，不增加手动按钮，也不牺牲预设和世界书修改后的正确性。

## 行为

- 首次使用或来源结构变化时读取当前预设和世界书。
- 连续生成且来源未变化时复用内存中的扫描结果。
- 酒馆触发预设保存、切换、删除或重命名事件时，让预设来源失效。
- 酒馆触发世界书更新事件时，只让对应世界书失效；世界书设置、聊天或角色上下文变化时让来源结构失效。
- 下一次生成自动更新失效部分，用户不需要操作按钮。
- 需要加载多本世界书时并行读取，但最终消息顺序仍按原世界书顺序。
- 旧版酒馆缺少部分事件时，通过当前预设名和世界书名称签名检查兜底。

## 边界与失败处理

- 首次生成仍可能发生一次完整扫描。
- 单本世界书读取失败不阻止其他世界书读取，维持现有错误记录行为。
- 未保存且未触发酒馆事件的内存篡改无法可靠检测；正常酒馆编辑保存流程会自动失效。
- 不持久化缓存，刷新页面后重新建立，避免跨版本脏数据。

## 验证

- 单元测试覆盖缓存失效、精确世界书失效和并行加载保持顺序。
- 源码集成测试确认生成路径不再每次强制扫描，并注册酒馆事件。
- 运行现有全量测试和语法检查。
