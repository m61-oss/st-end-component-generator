# 助手正文自动生成触发设计

## 问题

插件当前直接监听 SillyTavern 的全局 `GENERATION_ENDED`。这个事件也会在静默生成、用户模拟、后台记忆处理和手动停止时触发，因此第三方扩展生成 `user` 消息后，插件会错误地取上一条助手回复并生成状态栏。

## 目标

只有本轮 SillyTavern 生成确实产生或更新了助手正文时，才触发自动状态栏生成。

必须保留：

- 正常助手回复完成后自动生成。
- 重新生成、滑动回复和继续生成完成后自动生成。
- 自动注入继续作用于本轮目标助手消息。

必须排除：

- 只生成或插入 `user` 消息的后台任务。
- `quiet` 静默生成。
- `impersonate` 用户模拟生成。
- 系统消息。
- 没有产生助手正文的生成周期。
- 手动停止的生成周期。
- 同一生成周期的重复结束通知。

## 方案比较

### 只过滤生成类型

监听 `GENERATION_STARTED` 的类型并排除 `quiet`、`impersonate`。实现简单，但第三方扩展可能用普通类型执行后台任务，仍可能误触发。

### 比较生成前后的最后一条消息

只有最后一条消息变化时才触发。无法可靠覆盖原位更新的重新生成、滑动和继续生成。

### 关联真实助手消息事件

生成开始时建立一次监听周期；收到 `CHARACTER_MESSAGE_RENDERED` 后检查对应聊天消息确实是非用户、非系统的助手消息，并记录消息编号；生成结束后只对已记录编号触发。该方案直接验证最终产物，最符合“只监听正文”的含义，因此采用。

## 事件状态

新增一个可独立测试的自动触发跟踪器，负责：

1. `GENERATION_STARTED`：开始新周期并清空旧候选，记录生成类型和 `dryRun`。
2. `CHARACTER_MESSAGE_RENDERED`：只有活动周期、非 `quiet`、非 `impersonate`、非 `dryRun`，且对应消息为助手正文时，记录消息编号。
3. `GENERATION_STOPPED`：将当前周期标记为已停止。
4. `GENERATION_ENDED`：在下一个事件循环检查周期结果；只有存在有效助手消息且未停止时返回目标消息编号，并立即消费该周期，避免重复触发。

结束处理延迟一个事件循环，是因为 SillyTavern 手动停止时先发送 `GENERATION_ENDED`，随后才发送 `GENERATION_STOPPED`。

## 精确目标消息

自动入口将目标消息编号传给状态栏生成函数。生成提示词使用该编号对应的助手正文，不再重新搜索“最新助手消息”。

自动注入同样沿用该目标编号，避免外置 API 请求期间聊天记录发生变化后注入到其他回复。手动按钮和 Quick Reply 未提供目标编号时，继续使用当前最新助手消息，保持原行为。

## 兼容与失败处理

- 酒馆缺少某个可选事件时不抛错，自动触发只在可确认助手正文时运行。
- 目标消息在外置生成前已删除、变成用户消息或系统消息时，取消自动生成并提示找不到可用助手回复。
- 不修改手动生成、Quick Reply、重复生成保护和 API 调用逻辑。
